The correction memory is a variant of lexicon matching built from corrections people already make. An operator, a person using Ultron during an exercise, corrects transcripts there. Each correction of a misrecognized keyterm gives a rewrite: Whisper wrote X, the operator corrected it to keyterm Y. A rewrite is replayed on later transcripts only once the operator puts on it the automatic replay mark, an explicit mark that says this replacement is to be done automatically from now on. Rewrites without the mark are kept out of the table.

Replaying a rewrite needs no score and no match threshold. X and the transcript go through the same text normalization as in lexicon matching, and wherever the normalized X appears as whole words in the transcript, it is replaced by Y. When two marked rewrites cover overlapping words, the longer X is applied.

A correction made once, and not marked, stays a correction of that one transcript.

Distractor keyterms play no part. Lexicon matching compares the transcript with every keyterm of the lexicon, so each keyterm not said is one more string an ordinary word can fall close to. The correction memory never reads the lexicon: a keyterm can be written only through a marked rewrite, so its errors grow with the number of marked rewrites whose X is ordinary words, whatever the size of the lexicon.

next to the other two techniques

The correction memory fixes only errors that already happened and were corrected and marked. A keyterm new to a mission, or one Whisper misspells in a new way, needs lexicon matching by sound or the boosting tree, which work from the lexicon alone. The correction memory in turn fixes, with no threshold to tune, the errors that keep coming back. They complement each other.

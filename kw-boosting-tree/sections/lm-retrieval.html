Scoring every candidate span against every keyterm costs spans × keyterms comparisons, about 30,000 for one utterance with 1,000 keyterms. Fast candidate retrieval finds, without scoring every keyterm, the few keyterms close enough to a span to be worth scoring; only those get the full score of the spelling and the sound. Two indexes do it on spelling, built once per lexicon and queried for each span.

A character n-gram index maps each run of n characters (3 here, a character 3-gram) to the keyterms that contain it. « rivoli » holds « riv », « ivo », « vol », « oli ». For a span, its 3-grams are looked up, each keyterm gets the number of 3-grams it shares with the span, and the few keyterms with the most shared 3-grams go on to be scored. A misspelling changes the 3-grams around the wrong letter and leaves the others, so the right keyterm still shares most of them.

The index lookup costs one access per 3-gram of the span, whatever the lexicon's size; what grows with the lexicon is how many keyterms each 3-gram lists. The same idea works on sound: an index from each phonetic code to its keyterms returns, in one lookup, the keyterms whose code equals the span's.

A BK-tree indexes strings by edit distance. Each node holds a keyterm, and each child hangs under its parent at the edit distance between the two. To find every keyterm within distance k of a span, the search computes the span's distance d to a node, then visits only the children hung at a distance between d − k and d + k: by the triangle inequality of the edit distance, no keyterm under another child can be within k of the span.

The BK-tree returns every keyterm within k exactly, with no missed candidate, but only for a distance measured on whole strings; a large k, as long keyterms need, makes it visit most of the tree.

At the sprint's size, the gain is in milliseconds. A compiled library such as RapidFuzz scores the 30,000 pairs by spelling in a few milliseconds without any index, well inside the 3 s per utterance. The index pays when the score per pair is expensive, a phonetic code or a G2P computed on the span, or when the lexicon grows past a few thousand keyterms.

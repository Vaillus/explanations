The prefix tree is shared by all hypotheses, but each hypothesis keeps its own tree position: the node its last tokens have reached, that is, how much of a keyterm they match. At each decoding step, the children of that node are the tokens that continue a keyterm, and the children of the root are the tokens that start one. Both get the boosting weight.

When the hypothesis writes a token, its position makes a transition: if the token is a child of the current node, the position moves down to that child; if the child ends a keyterm, the keyterm is complete. When beam search extends one hypothesis by two different tokens, each extension carries its own copy of the position and moves on its own token.

When the token is not a child, the match breaks. Going back to the root would miss a keyterm that starts inside the tokens already matched. A failure link avoids that: it links each node to the node of the longest path from the root that ends with the same tokens, and the position follows it, then retries the token from there. Adding these links to a prefix tree is the Aho-Corasick algorithm (Aho and Corasick, « Efficient string matching: an aid to bibliographic search », Communications of the ACM, 1975), built so that every entry of a list is found in one pass over a text. The boosting-tree libraries of section 12 build their tree with it.

The player below runs one hypothesis on the tree of section 6 while Whisper writes « rue de Lattre ». The score change at each step is the accumulated boosting weight of the new position minus that of the old one.

A failure link that leads to the root is the common case: most tokens that break a match start no keyterm. The links to inner nodes matter when keyterms overlap, as street names sharing « de », « du » or « rue » do.

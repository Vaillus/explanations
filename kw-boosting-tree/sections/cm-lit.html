No paper measures the correction memory as section 19 defines it, a table of rewrites that people mark by hand for replay. Two papers measure close relatives, each covering one half of it: one learns from the corrections users make, the other replays a table of rewrites. A third, on the boosting tree, shows where a rewrite can go besides the transcript.

Yu, Hwang, Mau, Acero and Deng, « Unsupervised Learning from Users' Error Correction in Speech Dictation », Interspeech 2004 (Microsoft) take the corrections users make in a dictation system and adapt the speech-to-text model with them. A word the user typed in that the speech-to-text model did not know is added to its vocabulary, with a raised probability; a pronunciation is learned from the audio; a phrase just corrected is favoured for the rest of the dictation session. English, four users each dictating 2,000 to 4,000 words of e-mails, a speech-to-text model of the time, not Whisper.

The paper does not trust every edit. A user also edits text to change what they meant, so each edit is first scored, on the audio, for how likely it is the correction of a recognition error, and learned from only above a threshold. The automatic replay mark puts the operator's own judgment where that score was. The gain comes mostly from new words entering the speech-to-text model, which helps on every later utterance of the word, whatever Whisper's error would have been: a corrected keyterm is used from then on, much as one added to the lexicon of the boosting tree.

Sodhi et al., « Mondegreen: A Post-Processing Solution to Speech Recognition Error Correction for Voice Search Queries », KDD 2021 (Google) replay a table of rewrites on voice search queries, with no audio. The rewrites come from users: a spoken query that got no click, followed within 60 s by a query that got one, is taken as « the speech-to-text model wrote X, the user meant Y ». The table is stored as key and value pairs and looked up at run time with no added delay.

A pair is replayed only when the two queries are close in sound (an edit distance on their phonemes below a threshold) and when Y followed X in at least 10 or 20% of the times X was seen. The authors chose very high precision over coverage, since a wrong rewrite of a query is intrusive, and still added a way for the user to go back to the original transcription. The rewrites apply to 1.76% of queries. On those, the rewrite is closer to what the user typed next than both the original query and a trained rewriting model: BLEU, a score from 0 to 1 of how many runs of words a text shares with a reference text, is 0.79 against 0.59 for the trained model on the same queries. The paper reports clicks and abandoned queries, and no WER.

Mondegreen keeps its precision with filters the correction memory replaces by the mark: closeness in sound, and how often the same correction was made. A query never corrected before gets nothing, as an error never marked gets nothing from the correction memory.

Liu, Peng and Chng, arXiv 2508.17796, 2025, the Whisper paper of section 11, put into the prefix tree, next to each keyterm, extra keyterm variants spelled as Whisper tends to mishear the keyterm, generated from synthetic speech. When the best hypothesis ends on such a variant, it is written back as the keyterm. On LibriSpeech test-other with 1,000 distractor keyterms, this takes the cut in B-WER from 40% to 44%.

A marked rewrite has the same shape as one of those variants: X is a form Whisper wrote for keyterm Y. Entered as a path of the prefix tree that leads to Y, it would receive the boosting weight while Whisper writes, and Y would be written back. No paper measures variants that come from human corrections.

No paper measures a correction memory on Whisper, on French, or with a lexicon and distractor keyterms. The closest measure of replay at scale, Mondegreen, rewrites whole queries and reports search clicks. What the correction memory gains on Ultron depends on how many errors repeat and get marked, which only the exercises can show.

The boosting tree enters Whisper's decoding by shallow fusion: a score from outside the model is added to the model's log-probabilities at each decoding step, before pruning, and the model itself is not retrained. The same mechanism is commonly used to add the scores of a separate text-only model; here the outside score comes from the prefix tree.

The sum takes the form of a log-linear score combination. For a token t that extends a hypothesis:

score(t) = log PWhisper(t | audio, tokens so far) + λ · bias(t)

bias(t) is the change of accumulated tree score that writing t causes (one level of the tree when t continues a keyterm, a negative amount when it breaks one), and λ is the weight that scales it against Whisper's log-probabilities. With one unit per level, λ is the boosting weight; the TurboBias paper writes the same sum over a whole transcript as log P(W | X) + λ log PC(W), with PC the score of the tree (Andrusenko et al., « TurboBias », ASRU 2025, eq. 1). Too small a λ leaves a rare keyterm below the cut; too large a λ lets keyterms in where they were not said. Papers pick λ on a set of utterances kept apart from the test set.

In code, shallow fusion sits in a logits processor: a function the decoder calls at each decoding step, which receives the tokens of every hypothesis and the scores of every next token, and may change those scores before beam search picks. In Hugging Face transformers it is a LogitsProcessor with __call__(input_ids, scores): input_ids holds each hypothesis's tokens, from which the processor finds its tree position, and scores holds one row per hypothesis to which it adds the boosting weights. In beam search the processors receive scores already turned into log-probabilities, so the added weight stays as it is. openai-whisper has the same hook, LogitFilter.apply(logits, tokens), but it runs before the scores are normalized into log-probabilities, so part of a weight added there is undone by that normalization.

At each decoding step, Whisper gives a hypothesis a log-probability for every one of the 51,866 tokens of its vocabulary. The boosting tree adds to a handful of them the boosting weight, a fixed positive number, of the order of 1 in the papers and libraries that use it. Papers and libraries give it other names (bias weight, context score, hotwords score); the report calls it the boosting weight throughout.

The tokens that get it depend on what the hypothesis has written so far, which the boosting tree keeps as the hypothesis's tree position: the node of the prefix tree its last tokens have reached. At the root, the hypothesis is inside no keyterm. The tree position fixes the boosted tokens, the tokens that get the boosting weight at the next decoding step: the children of its node, which continue the keyterm in progress, and the children of the root, which start a keyterm, since one can start anywhere in the transcript. Every other token keeps the log-probability Whisper gave it, the tokens deeper in the tree included.

The player follows one hypothesis while Whisper writes « rue de Rivoli », on a tree of three keyterms and a vocabulary cut down to ten tokens.

If the token a hypothesis writes is a child of the node at its tree position, the tree position makes a transition: it moves down to that child, as the ring does at each step of the player. A keyterm of four tokens thus collects the boosting weight four times once complete. When the hypothesis leaves a keyterm incomplete, what it collected for it is taken back.

Beam search keeps several hypotheses at each decoding step, and each one keeps track of its own tree position, so the same token can be boosted for one hypothesis and not for another.

Adding a score from outside the model to its log-probabilities at each decoding step, before pruning, without retraining the model, is called shallow fusion; the same mechanism adds the scores of a separate text-only model. It takes the form of a log-linear score combination, for a token t that extends a hypothesis:

score(t) = log PWhisper(t | audio, tokens so far) + λ · bias(t)

For the boosting tree, λ is the boosting weight and bias(t) is 1 for a boosted token and 0 for any other token, except a token by which the hypothesis leaves a keyterm in progress, whose bias is negative so that what the hypothesis collected is taken back.

The player follows one hypothesis choosing among its own next tokens. Pruning compares the hypotheses with each other, and that is where the boosting weight decides whether a keyterm stays in the beam.

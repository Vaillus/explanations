The boosting weight is paid token by token, before Whisper knows whether the keyterm will be completed. Many keyterms start with a token that also starts ordinary words: « Leclerc » starts with " Le", the French article at the head of a sentence. If the weight stayed, every hypothesis that writes « Le » and then any other word would keep it, and the search would favour hypotheses that start keyterms and never finish them. Withdrawal subtracts the boosting weights a hypothesis received for a keyterm it leaves incomplete, when its tree position falls back.

Each node of the prefix tree stores the boosting weight accumulated from the root to it, and a token changes the hypothesis's score by the accumulated weight of the node it lands on minus that of the node it leaves. The weight a hypothesis holds is then always the accumulated weight of its tree position, plus the weight of the keyterms it completed: a completed keyterm keeps its weight, since the node that ends it falls back at no cost, as in TurboBias, NVIDIA's boosting tree run on the GPU (Andrusenko et al. 2025, whose results section 11 reads).

With withdrawal, the boosting weight still lifts « Le » during the steps in which beam search prunes, so a real « Leclerc » stays in the beam until its last token, and a hypothesis that turns out to write ordinary words ends with the score Whisper alone gives it.

At the end of the transcript

The last case of the player is a hypothesis that stops inside a keyterm. The end-of-text token is a child of no node, so treating it as one more token that falls back to the root withdraws what the hypothesis holds on that token's score. The icefall library does this in ContextGraph.finalize, which subtracts the accumulated weight of the hypothesis's last position. In Whisper's beam search the extensions by the end-of-text token are sorted with the other extensions (section 4), so this withdrawal acts both when the hypothesis finishes and in the final ranking. Without it, a finished hypothesis keeps the weight of a keyterm it never completed.

The reverse problem exists too. In a model that, like Whisper, writes until it writes an end token, the boosting weights given to keyterm tokens can outscore the end-of-text token, and the model keeps writing keyterm tokens after the speech has ended. TurboBias adds to the end-of-text token's score, at each step, the largest boosting weight the tree can give, plus the weight of a keyterm just completed, so that ending the transcript stays competitive (Andrusenko et al. 2025, section II.C).

The boosting tree is the technique that biases Whisper while it writes: during beam search, it raises the score of the tokens that start or continue a keyterm, so that a hypothesis spelling a keyterm survives pruning. To know which tokens those are, it first puts the lexicon in a tree of tokens, built once before decoding.

The tree is a prefix tree (a trie): each edge is a token, each path from the root spells the tokens of one keyterm, and keyterms that share their first tokens share the start of their path. A node marked as an end closes a complete keyterm. Below, a lexicon of five keyterms in Whisper's real tokens. « rue de Rivoli » and « rue de Rennes » share " rue" " de" and split after it. « Leclerc XLR » continues « Leclerc », so the node that closes « Leclerc » sits in the middle of a path, not at its end.

A keyterm has several token sequences. In Whisper's tokenizer the space before a word belongs to the word's first token, and case changes the tokens: " Leclerc" is " Le" "c" "ler" "c", " leclerc" is " le" "c" "ler" "c", and " LECLERC" is " L" "EC" "LER" "C". Each keyterm variant, one token sequence a keyterm can take, goes into the tree as its own path, or the boosting tree never favours that form. The tree above holds two variants of « Leclerc »: their first tokens differ, so they start two paths from the root.
